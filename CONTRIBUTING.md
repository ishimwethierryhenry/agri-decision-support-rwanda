# Contributing to Team 8

Thank you for contributing to the CMU-Africa agriculture decision support practicum repository.

## Team workflow

1. Create a task-specific branch from the current mainline, for example `feat/crop-recommendation-cleaning`, `docs/api-contracts`, or `fix/image-validation`.
2. Make focused changes and avoid unrelated edits to another workstream.
3. Run relevant checks or tests when they are available, and explain any checks not run.
4. Commit with a clear, descriptive message such as `docs: record dataset licensing notes`.
5. Open a pull request for team review, link the task or GitHub Issue, and summarize the changes and checks.
6. Update documentation whenever functionality, datasets, preprocessing, models, evaluation, or APIs change.

## Collaboration and safety

Use short, lowercase, hyphenated branch names with a purpose prefix like `feat/`, `fix/`, `docs/`, or `chore/`. Resolve review feedback before merging and coordinate interface changes with both workstreams.

Never commit credentials, API keys, passwords, `.env` files, personally sensitive material, or restricted datasets. Respect dataset licences, privacy rules, and approval requirements. Reference approved external data locations instead of committing large raw datasets, images, or trained model weights. Discuss Git LFS or other storage only if the team approves it. Keep results reproducible, distinguish measured outcomes from plans, and align contributions with the approved Statement of Work.
